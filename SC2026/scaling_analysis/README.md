# Scaling Analysis

Weak and strong scaling experiments for GGap on OLCF Frontier using synthetic forest data.

## Overview

- **Weak scaling**: Fixed 10 sites/GPU, scales from 8 to 2,048 GPUs (80 to 20,480 sites). Measures parallel efficiency.
- **Strong scaling**: Fixed 2,048 sites total, scales from 8 to 512 GPUs. Measures speedup and cross-rank communication overhead.

Both experiments use synthetic forest data on a 2D torus grid with Moore neighborhood (8-neighbor) connectivity.

## Reproduction Workflow

All commands run from the `scripts/` directory.

### Step 1: Generate synthetic input data

```bash
cd scripts
python create_synthetic_csv.py
```

Creates 6 CSV files in `input_data/`: `SYNTHETIC_{specieslist,site,climate,climate_stddev,rangelist,altitudes}.csv` (25,000 sites, 100 species). This covers all scaling experiments up to 2,048 GPUs. Only needs to be run once.

### Step 2: Run scaling experiments

**Important**: Submit jobs from the `scripts/` directory.

```bash
cd scripts
sbatch submit_weak_scaling.sh
sbatch submit_strong_scaling.sh
```

Each submit script loops over node counts, running the experiment at each scale point sequentially within one SLURM job.

### Step 3: Output

Each experiment appends one row per GPU count to its CSV file:

| File | Description |
|------|-------------|
| `results/weak_scaling.csv` | Per-tick timing breakdown for each GPU count (8, 16, ..., 2048) |
| `results/strong_scaling.csv` | Per-tick timing breakdown for each GPU count (8, 16, 32, 64, 128, 256, 512) |

CSV columns include: `num_gpus`, `mean_tick_time`, `simulation_time`, `mean_gpu_execution`, `mean_mpi_total`, `gpu_execution_fraction`, `mpi_fraction`, and detailed phase breakdowns (gpu_compute, gpu_sync, data_prep, kernel_args_build, write_back, mpi_gpu_pack, mpi_exchange, mpi_wait_time, mpi_gpu_unpack).

### Step 4: Generate figures

The CSV results are consumed by plotting scripts in `../figures/scripts/`:

```bash
cd ../../figures/scripts

python strong_scaling_speedup.py      # Speedup + cross-rank communication
python weak_scaling_efficiency.py     # Parallel efficiency
python phase_breakdown.py             # Per-phase timing decomposition
python setup_amortization.py          # Setup cost amortization
```

**Output**: PDF + PNG figures in `../figures/figs/`.

## Output-to-Figure Map

| CSV File | Figure Script | Paper Figure |
|----------|--------------|--------------|
| `results/strong_scaling.csv` | `strong_scaling_speedup.py` | **Strong scaling speedup** (log-log speedup + cross-rank edge fraction) |
| `results/strong_scaling.csv` | `phase_breakdown.py` | **Phase breakdown** (stacked timing decomposition) |
| `results/weak_scaling.csv` | `weak_scaling_efficiency.py` | **Weak scaling efficiency** (parallel efficiency vs GPU count) |
| `results/weak_scaling.csv` | `setup_amortization.py` | **Setup amortization** (setup cost vs simulation time) |

## Experiment Parameters

| Parameter | Weak Scaling | Strong Scaling |
|-----------|-------------|----------------|
| Sites | 10/GPU (scales with GPUs) | 2,048 total (fixed) |
| Grid | height=5 | height=4 |
| Gaps/site | 500 | 200 |
| Trees/gap | 1,000 | 500 |
| Ticks | 1,000 | 1,000 |
| GPU counts | 8, 16, 32, 64, 128, 256, 512, 1024, 2048 | 8, 16, 32, 64, 128, 256, 512 |

Note: The included `results/weak_scaling.csv` and `results/strong_scaling.csv` contain our experiment results and can be used directly for figure generation. Re-running the experiments will produce similar but not identical results due to system-level variability.

## Scripts

| Script | Purpose |
|--------|---------|
| `create_synthetic_csv.py` | Generates synthetic forest input data (species, sites, climate) |
| `weak_scaling.py` | Weak scaling experiment runner (called by submit script with MPI) |
| `strong_scaling.py` | Strong scaling experiment runner (called by submit script with MPI) |
| `submit_weak_scaling.sh` | SLURM submission: loops 1-256 nodes, 10 sites/GPU |
| `submit_strong_scaling.sh` | SLURM submission: loops 1-64 nodes, 2048 fixed sites |
